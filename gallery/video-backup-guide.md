# 视频导出、格式与长期备份指南

> 来源：Qoder 对话整理（2026-08-02）
> 场景：华为手机 4K HEVC 原片，需要裁剪/剪辑后仍保持小体积、且长期保存

## 1. 为什么剪辑导出后文件反而变大

**文件大小由码率决定，不是分辨率或时长。**

| 因素 | 说明 |
|---|---|
| 编码格式转换 | 手机原片是 H.265/HEVC，很多编辑器（华为内置、Premiere 默认）导出转成 H.264，同画质下码率需 1.5~2 倍 |
| "原尺寸"只保分辨率 | 裁成 2160×2160 后，导出器仍按 2160p 档位给高码率，不随像素减少而降低 |
| 关键帧更密 | 剪辑软件导出 GOP 通常比相机原片短，体积增加 20~30% |
| 色深 | 原片 10bit，导出 8bit，重编码有时反而更耗码率 |

**Premiere 为什么不默认用源编码：** 导出是"交付"步骤（发给谁就按谁的标准），不是"转换"步骤；加上 H.265 专利费高、兼容性考虑，默认永远是 H.264。它面向专业流程，默认值是"全世界都能播"，不是"和原片一样大"。

## 2. 解决方案

### 2.1 只剪时间（不裁剪画面）——无损切割

用 LosslessCut（https://github.com/mifi/losslesscut）或 ffmpeg 按关键帧切割，体积画质完全不变：

```bash
ffmpeg -i 原片.mp4 -ss 00:01:00 -to 00:02:00 -c copy 输出.mp4
```

### 2.2 裁剪成正方形 + 压缩——ffmpeg 直出

裁剪必须重编码，用 H.265 + CRF 质量参数：

```bash
ffmpeg -i 原片.mp4 -vf "crop=2160:2160:(iw-2160)/2:0" -c:v libx265 -crf 22 -preset medium -c:a copy 输出.mp4
```

- CRF 22 ≈ 接近原片画质；想更小用 24~26

### 2.3 坚持用 Premiere

- 导出格式选 **HEVC (H.265)**
- 码率选 VBR 2-pass，4K 30fps 目标码率 40~60 Mbps
- 别用默认 H.264 高码率预设

## 3. 格式"战未来"——结论：别为编码焦虑，为备份焦虑

- H.264（2003）至今仍是全兼容底线；MP4（2001）仍在用；解码器生态永远向下兼容
- 磁带难看的本质：物理介质退化 + 播放硬件消失。数码文件不退化、复制无损、开源解码器（ffmpeg）不会消失
- **真正杀死视频的（按概率）**：硬盘坏/丢失 → 网盘/平台压缩删库 → DRM → 格式淘汰（概率最低）

### 选格式原则

- 原片永不动，不重编码——手机 HEVC/MP4 原片就是最好的档案格式
- 容器 MP4，编码 H.264（最稳）或 AV1（免费开放、未来趋势）；避开 DRM、专有 RAW、冷门编码
- 保底：只要没加密，任何格式将来都能用 ffmpeg 转出

## 4. 备份方案（个人版）

企业"两地三中心"是数据中心级概念，个人用 **3-2-1** 就够：3 份副本、2 种介质、1 份异地。

### 推荐配置：2 云 + 1 盘（适用于没有第二住处的情况）

- **本地盘**：固定放书桌抽屉，命名"备份盘"，不许乱放
- **主力云**：跟生态走（iCloud / 华为云 / 百度），开相册原片自动备份
- **冷备云**：中立便宜的一家（Google One / OneDrive / 夸克），每半年手动同步一次
- 两家不同公司网盘同时倒闭概率 ≈ 0；别买 5 家，维护成本会压垮执行力

### 组织方式

```
/家庭视频/
  2024-婚礼/        ← 原片，永不动
  2025-孩子满月/
  说明.txt          ← 编码=HEVC, 分辨率=4K, 检查日期
  校验和.txt        ← shasum 生成
```

### 每 5 年体检

```bash
shasum -c 校验和.txt                          # 查文件损坏
ffmpeg -v error -i 视频.mp4 -f null -         # 查解码是否正常
```

归档是"定期维护"不是"一次性存放"：校验、换盘、必要时换格式。数码时代这些操作无损，磁带时代做不到——这就是磁带输掉的原因。
